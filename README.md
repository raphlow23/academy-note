# 수봉화실

개인용 수강생·수강권·예약 달력 웹앱입니다. 화면은 GitHub Pages의 정적 파일로 제공하며 로그인한 사용자의 Google Drive/Sheets API에 직접 연결합니다. Apps Script는 사용하지 않습니다. 로그인 유지에만 Cloudflare Workers/SQLite Durable Objects을 사용하며 수강생·납부·예약 자료는 기존 Google 시트에 저장합니다.

## 데이터 소유와 보안

- Google 로그인 및 `drive.file` 권한으로 앱이 만들거나 사용자가 선택한 파일만 연결합니다.
- 본인 소유의 시트를 생성하며, 공유는 소유자가 이메일을 지정한 경우에만 허용합니다. 공유받은 사람은 앱에서 다시 공유할 수 없습니다.
- 수강생·납부·예약 자료와 인증 비밀 정보는 이 저장소에 포함하지 않습니다. 조회한 기록은 실행 중 메모리에 두며, 전송 대기 중인 변경만 계정별 기기 저장소에 보관해 다음 연결 때 재시도합니다.
- 브라우저에는 무작위 앱 세션과 계정별 선택 파일 ID를 보관합니다. Google 갱신 토큰은 브라우저로 보내지 않으며 인증 서버 전용 저장소에 암호화해 저장합니다. 액세스 토큰은 실행 중 메모리에 사용하고 만료 전 자동 갱신합니다. 기존 인증의 기기 저장값은 새 인증에서 사용하지 않습니다.
- 같은 Google OAuth 클라이언트와 drive.file 범위를 유지하므로 기존 시트와 공유 권한을 계속 사용합니다. 로그아웃은 해당 기기 세션만 종료합니다. 180일 미사용, Google 권한 철회, 기기 저장소 삭제 시 다시 로그인해야 합니다.
- 웹앱 설정의 OAuth Client ID와 Google Picker의 제한된 API Key는 공개 웹 클라이언트 설정값입니다. 클라이언트 비밀번호와 토큰 암호화 키는 Worker Secrets에만 보관합니다. 인증 서버 소스와 운영 안내는 `auth-server/`에 있습니다.

## 저장과 동시 수정

### 자동 확정과 홈 이동

- 수강생·납부·예약·시간표·휴무 폼에서 필수 입력을 마치고 4초간 변경이 없으면 버튼 없이 확정합니다. 납부 금액은 사용자가 입력하거나 해당 칸을 확인한 후에만 자동 확정합니다. 기존 버튼으로 바로 저장할 수도 있습니다. 한글 조합 중과 다른 저장 중에는 기다립니다.
- 명령은 인증 갱신이나 네트워크 요청보다 먼저 계정별 대기열에 동기적으로 기록합니다. 홈 이동 시에도 완성된 폼을 제출하고 검증된 요청을 같은 작업ID의 keepalive 전송으로 보냅니다. 전송 시작을 저장 완료로 표시하지 않습니다.
- 모바일 OS가 웹앱을 즉시 중단하거나 인터넷이 끊기면 백그라운드 완료는 보장되지 않습니다. 확인되지 않은 명령은 기기에 남겨 다음 실행 때 재검증·중복 없이 저장합니다. 대기 중에는 기기 저장소를 삭제하지 마세요.

### 구글 시트 직접 입력

- 데이터 보관의 전체 기록 구글 시트는 기존 원본입니다. 전체 엑셀 다운로드에 조회용 표·정확한 작업 이력·설정 이력·직접 입력 탭이 함께 포함됩니다.
- 기존 기록을 그대로 두고 `입력_수강생`, `입력_수강권납부`, `입력_예약`, `시트입력안내`를 추가합니다. 새 행을 작성하면 앱 접속/새로고침 후 학생 → 납부 → 예약 순서로 검증해 같은 작업기록에 추가합니다. 첫 화면의 로그인과 자료 표시를 이 작업이 막지 않도록 뒤에서 확인합니다.
- ID는 자동 발급하며 동명이인과 여러 수강권은 ID로 지정합니다. 기존 학생 수정에는 원래 수정버전이 필요하고 납부는 새 거래만 추가합니다. 기존 예약 취소는 1회 복구하며 날짜/시간 변경은 취소 후 새 행에 예약합니다.
- `반영 완료`/`확인 필요`를 표시하고, 같은 입력 재시도와 여러 기기 동시 반영도 같은 작업ID로 중복 등록을 막습니다. 반영 중 다시 편집된 입력 행은 ID·확인값으로 덮어쓰지 않습니다. 조회용 표·작업기록·숨겨진 원본은 직접 수정하지 마세요.
- 정상 입력은 실제 도메인 검증을 사용합니다. 오류 행을 기존 원본으로 덮어쓰거나 전체 자료를 교체하지 않습니다. 시트의 셀 자체는 Google이 자동 저장하며 앱 화면 반영은 다음 앱 연결 시 이루어집니다.

### 로그인 조회 최적화

인증 서버가 이미 확인한 Google 계정을 브라우저에서 다시 userinfo로 조회하지 않습니다. 로그인 때 받은 최신 파일 권한 정보를 최초 자료 읽기에 재사용해 중복 Drive 조회도 줄였습니다. 기록을 기기에 캐시해 대신 표시하지 않으며 Google Sheets 접근 권한 검증은 계속 적용됩니다.

변경 요청을 Google Sheets의 `작업기록`에 추가하고, 행 순서에 따라 검증·적용합니다. 같은 마지막 1회권을 여러 기기에서 동시에 예약하면 먼저 기록된 유효한 요청만 적용합니다. 동일 작업 ID의 재전송은 중복 적용하지 않습니다. 작업기록을 삭제·정렬·직접 수정하면 안 됩니다.

적용된 결과는 조회용 수강생·수강권납부·예약·수강현황에 실제 셀 값으로 표시합니다. 수식 재계산 없이 구글 시트와 엑셀에서 같은 기록을 확인할 수 있습니다. 인터넷/브라우저가 저장 도중 종료되면 처리 대기가 남을 수 있으므로 ‘완료’ 표시를 확인하세요. 다음 연결에서 대기 기록을 검증합니다. 원본 시트와 내려받은 백업은 웹앱과 독립적으로 보관됩니다.

## 기능

- 화면 높이에 맞춘 월 달력과 요일별 30분 단위 수업 타임
- 예약 시 1회 차감, 취소 시 복구, 완료 시 추가 차감 없음
- 1일 클래스는 타임 안에서 30분 단위 수강 길이 선택
- 재원 중 내일 이후 예약이 없는 수강생을 위에, 다음 예약이 있는 수강생을 그다음에 표시하고 각 구역은 한글 이름순으로 정렬
- 예전 수강생은 하단 별도 구역에 표시
- 잔여 횟수 옆 소진·재등록 표시, 마지막 예약의 마지막 수업 표시
- 납부 날짜·금액·충전 횟수·누적 수강·등록 기간
- 정기 요일 휴무와 기간 휴무
- 선택 공유, 전체 CSV/JSON/오프라인 열람본, Google Sheets 엑셀 다운로드와 인쇄/PDF

## 기존 자료

데이터 보관의 파일 선택에서 이전 수봉화실 시트를 선택하면 새 본인 소유 시트에 복사해 연결합니다. 이전 원본은 변경하지 않습니다. 기존 공유 권한은 복사하지 않으므로 필요하면 새 자료에서 다시 허용하세요.

## 개발·검증

Node.js 22 이상에서 `npm test`로 검증합니다. 정적 서버로 연 뒤 `?preview`를 붙이면 localhost에서만 읽기 전용 예시가 표시됩니다. 배포 주소에서는 예시 자료를 표시하지 않습니다.

`config.js`에 Google OAuth Web Client ID, Picker API Key, 같은 Google Cloud 프로젝트 번호를 설정해야 실제 로그인이 가능합니다. OAuth 허용 JavaScript 원본과 Picker 키의 HTTP referrer를 배포한 HTTPS 주소로 제한하세요. 카드 등록·과금 계정은 이 앱의 요구 사항이 아닙니다.

무료 서비스의 한도와 미래 정책은 해당 제공자의 조건을 따릅니다. 평생 무료·무제한·영구 보존을 보장하지 않습니다.

### 시간표 적용일과 날짜별 예약 창
수업 시간 변경에는 내일 이후의 적용 시작일이 필요합니다. 이전 시간표를 이력으로 보관하고 달력·예약 검증은 조회 날짜에 적용되는 시간표를 사용합니다. 완료된 수업과 이미 등록한 미래 예약의 시작·종료 시간은 변경하지 않습니다. 이전 앱에서 기록한 작업은 기존 방식으로 재생하며, 새 저장 요청에는 적용일이 있어야 합니다.

달력 날짜를 누르면 전체 타임의 예약 현황 창이 열립니다. 타임의 + 버튼으로 예약 창을 열면 날짜·타임이 자동 선택됩니다. 작은 화면에서는 현황 창 안에서 스크롤할 수 있습니다.

### 로그인 자동 준비
로그인하면 기존 본인 저장 공간을 먼저 연결하고, 없으면 본인 소유 비공개 시트를 자동으로 만듭니다. 저장 공간이 하나면 선택란을 숨기며 여러 공간은 내 학원·공유 학원이라는 짧은 이름으로 표시합니다. 목록 조회 실패를 빈 공간으로 간주해 새 파일을 만들지 않습니다.

## 수업 시작 시 완료
- 한국시간의 예약별 저장된 시작 시각이 되면 조회/내보내기 때 자동으로 완료 작업을 저장합니다. 취소 건 제외, 추가 차감 없음.
- 앱 활성 상태에서는 30초 간격으로 확인하며, 입력 폼 작성 중에는 저장 충돌을 피하려고 완료 동기화를 미룹니다. 앱 종료·오프라인·연결 만료 중에는 다음 연결 때 반영합니다.
- 완료 예약도 취소 가능: 1회 복구 및 월/누적 완료 집계에서 제외. 실제 납부금액·원래 시간은 유지합니다.

## 수강 등록 + 첫 예약
- 신규 학생 폼에서 수강권/납부를 함께 입력하고 선택적으로 첫 예약을 추가할 수 있습니다. 학생 정보만 등록도 지원합니다. 기존 학생의 납부 폼에도 예약 입력을 추가했습니다.
- 전체 요청을 사전 검증한 뒤 학생/수강권/예약 작업을 한 번의 append로 저장합니다. 각 기록 ID를 재사용하여 응답 유실 후 재시도해도 중복 납부/예약을 만들지 않습니다. 동시 변경으로 일부 거절된 경우 저장된 내역을 알리고 보존합니다.
- 등록은 금융 결제가 아닌 납부 기록입니다. 예약 시 1회만 사용하고 금액은 차감하지 않습니다.

## 이름을 눌러 작은 정보창
- 수강생 명단·하루 시간표의 이름을 누르면 410px 이내 정보창을 엽니다. 예약 이름은 해당 예약의 일시/상태/취소·복구를 포함합니다. 시간표의 인라인 예약 상세 펼치기는 제거했습니다.
- 자세히 보기 → 전체 기록. 브라우저 뒤로가기로 전체 기록 → 작은 정보창 → 기존 시간표 순서로 돌아갑니다. 작은창/전체 기록 바깥 터치도 닫힙니다. 인쇄용 전체 상세는 유지합니다.

## 정기 휴무 적용일과 이력
- 정기 휴무에 오늘 이후 적용 시작일을 지정합니다(기본 내일). 해당일부터 다음 변경 전까지 적용하며, 첫 변경 시 기존 요일을 기준 이력으로 보존합니다.
- 과거 날짜의 정기 휴무는 변경하지 않습니다. 여러 미래 적용일과 정기 휴무 없음도 지원합니다. 기간 휴무는 각각 지정한 시작/종료일로 계속 적용합니다.
- 새로 휴무가 되는 날짜의 현재·미래 예약 충돌은 저장 전에 막습니다. 시간표 변경과 정기 휴무 이력은 서로 보존합니다.
- 수업시간 설정의 일~토 선택은 아이폰에서도 7열 한 줄입니다.

## 아이패드 화면 배치와 바로가기 재실행
- 하단 안내를 제목 옆 상단으로 이동. 모바일에서는 제목 아래로 자동 줄바꿈. 사이드바 계정 버튼도 메뉴 아래에 배치합니다.
- visualViewport와 safe-area를 반영해 월 달력+범례가 실제 화면 높이에 들어오도록 계산합니다. 월 요약은 예약/완료 두 개만 렌더링합니다.
- 홈 화면 웹앱 종료 후에도 만료되지 않은 구글 연결을 기기 저장소에서 복원합니다. 로그아웃은 토큰을 제거하고 null 표식으로 예전 탭의 연결 부활을 막습니다. 다른 탭의 계정 변경·로그아웃은 storage 이벤트로 현재 화면도 연결 해제합니다. 구글 권한 만료 후에는 재연결이 필요합니다.

## 좌우 스와이프로 메뉴 이동
- 왼쪽 밀기: 다음 메뉴, 오른쪽 밀기: 이전 메뉴. 첫/마지막 메뉴에서는 순환하지 않습니다.
- 34px 가로 밀기 또는 22px 이상 빠른 밀기를 처리합니다. 처음 이동 방향을 구분해 세로 스크롤을 유지하며, 가로 터치만 브라우저 기본 동작을 막습니다. 핀치, 화면 가장자리 28px, 입력 컨트롤, 작은창과 저장 중에는 제외합니다. 기존 메뉴 클릭 동작과 권한을 그대로 사용합니다.

## 페이지 슬라이드와 앱 업데이트
- 메뉴 상태를 즉시 갱신하고 실제 pageStage에 Web Animations 좌우 슬라이드(220ms)를 적용합니다. 네이티브 View Transition 스냅샷은 입력을 가로막을 수 있어 메뉴 전환에 사용하지 않습니다. 이동 방향은 메뉴 순서 기준이며 모션 줄이기 설정은 존중합니다.
- 앱 시작·전면 복귀·온라인 복귀·활성 상태5분 간격에 index.html을 매번 다른 _check 쿼리와 no-store로 검사합니다. 현재 실행 HTML의 module/stylesheet 주소와 다르면 새 버전으로 판단합니다. 향후 배포도 app.js 또는 theme.css 버전 주소를 갱신해야 합니다.
- 저장/입력창/설정 초안/전환 중이 아니면 캐시를 우회하는 _app URL로 자동 재로드합니다. 작성 중에는 업데이트 안내만 표시합니다. 새로고침은 앱 버전과 기록 모두 확인합니다. 계정 메뉴의 앱 최신 버전 다시 불러오기는 수동 강제 재로드이며 연결 저장소를 지우지 않습니다.
- 기존 업데이트 확인 기능이 없는 바로가기는 최신 쿼리 주소를 Safari에서 열어 홈 화면에 다시 추가하는 최초1회 전환이 필요할 수 있습니다. manifest id는 고정하고 초기 start_url에 새 버전 쿼리를 사용합니다.

## 로그인/연결 새로고침 시 업데이트
- 공통 load 완료 시 최신 버전을 강제 확인합니다. 신규 로그인, 구글 계정 재연결, 자동 로그인 복원, 기록 새로고침/관리 공간 전환 모두 해당합니다. 연결 오류가 있어도 버전 확인을 실행해 새 코드로 복구할 수 있습니다.
- 로그인·자료 읽기를 버전 확인이 지연시키지 않도록 비동기로 실행합니다. 강제 확인은 이미 실행 중인 확인을 기다린 다음 다시 요청하므로 로그인 전의 오래된 확인 결과를 재사용하지 않습니다. 안전할 때 캐시 우회 재로드하고 유효 토큰은 유지합니다.

## 스크롤 경계 고정

## 구글 저장 확인과 종료 복구

- 전송할 명령만 계정 sub별 기기 localStorage에 먼저 임시 보관합니다. Google 반영·확인 후 삭제하며 전체 원본 자료를 기기에 별도 저장하지 않습니다. 저장 버튼 이전의 폼 초안은 이 대상이 아닙니다.
- 앱 종료/연결 끊김/응답 유실 뒤 같은 계정으로 열면 미전송 내용을 먼저 복구합니다. foreground/online/활성 30초 간격 재시도와 수동 저장 재시도를 제공합니다.
- 기존 이벤트 ID로 재시도하며 등록·납부·예약 일괄 명령은 고정 이벤트 ID를 사용합니다. 다른 계정의 대기 명령은 읽거나 전송하지 않습니다. Web Locks 지원 환경에서 같은 계정의 여러 탭 쓰기를 직렬화합니다.
- 저장 대기 중에는 업데이트/계정 전환을 막고 브라우저가 지원하면 페이지 나가기 경고를 표시합니다. 처리 중 메뉴 이동과 작은창 닫기도 막습니다. 작은 API 쓰기는 keepalive로 전송 지속을 요청합니다.
- iOS 홈 버튼·강제 종료 및 백그라운드 통신은 보장할 수 없습니다. 그때의 대기 명령은 같은 기기·브라우저·계정으로 다시 열어 저장합니다. Google 연결 만료 시 재로그인이 필요하고, 저장 완료 전 기기 저장소를 삭제하면 임시 내용은 복구할 수 없습니다.
- Google 저장 확인/대기 상태를 구분합니다. 전송 전·후 종료 복구, 계정 분리, 중복 방지, 기기 저장소 부족 등을 포함한 77개 테스트 통과. 실사용 시트를 테스트 목적으로 수정하지 않았습니다.
